# Выкатка и откат

Как доставить изменения на телефон и что делать, когда там что-то сломалось.

## Два канала доставки

| Что меняется | Как доставляется | Сколько ждать |
|--------------|------------------|---------------|
| JS, стили, тексты, промпты, логика SRS | `pnpm ota` | ~2 минуты |
| Нативные модули, `version`, иконки, разрешения | новая сборка APK | ~15 минут |

Правило простое: если в диффе нет новых зависимостей с нативным кодом и не
тронут `app.config.ts` — это OTA. Иначе APK.

## runtimeVersion: почему он важен

`app.config.ts` задаёт `runtimeVersion.policy = "appVersion"`, то есть runtime
равен полю `version`. OTA-обновление доезжает **только до тех APK, у которых
runtime совпадает**.

Это защита, а не формальность: если вы добавили нативный модуль и отправили JS,
который его зовёт, по OTA на старый APK — приложение упадёт на устройстве, где
этого модуля физически нет. Поэтому:

> **Добавили нативную зависимость → поднимите `version` в `app.config.ts` и
> соберите APK.** Старые сборки просто перестанут получать обновления, что и
> требуется.

История версий:
- `1.0.0` — MVP. Сборки от 2026-06.
- `1.1.0` — добавлены `expo-notifications` (нативный) и `ts-fsrs` (чистый JS).
  Требует новой сборки APK; APK 1.0.0 обновления больше не получают.

## Обычная выкатка (JS)

```bash
pnpm typecheck && pnpm test     # оба должны быть зелёными
pnpm ota                        # публикует в канал preview
```

На телефоне: приложение проверяет обновление при старте молча и скачивает;
применяется при следующем запуске. Принудительно — Настройки → Обновления →
«Проверить обновление» → «Перезапустить с обновлением».

## Сборка APK

```bash
pnpm build:apk:preview          # EAS, ~15 минут, ссылка на скачивание
pnpm build:apk:local            # локально, если EAS недоступен
```

После установки нового APK канал OTA снова работает — уже для нового runtime.

## Когда на телефоне что-то сломалось

Сценарии от лёгкого к тяжёлому.

### 1. Приложение работает, но фича сломана

Откатить последнюю выкатку на предыдущую:

```bash
npx eas-cli update:list --branch preview   # найти id рабочей группы
npx eas-cli update:republish --group <GROUP_ID>
```

Пользователь перезапускает приложение и получает старую версию.

### 2. Приложение падает на старте после OTA

Самый неприятный случай: новый JS настолько сломан, что до экрана дело не
доходит и «Проверить обновление» нажать негде. Тогда — откат на бандл, вшитый
в APK. Он заведомо рабочий, потому что с ним APK собирался:

```bash
npx eas-cli update:roll-back-to-embedded --branch preview
```

Клиенты при следующем запуске возьмут встроенную версию. Никаких действий на
телефоне не требуется, кроме перезапуска.

### 3. Совсем всё плохо

Переустановить APK: EAS хранит собранные артефакты, `eas build:list` даёт
ссылку на любую прошлую сборку. Данные приложения (словарь, прогресс) лежат в
SQLite и переустановку **не** переживают — экспорта пока нет, это известное
ограничение.

## Что проверять перед выкаткой

Минимум, без которого выкатывать нельзя:

```bash
pnpm typecheck                  # все три пакета
pnpm test                       # 178 тестов
```

Дополнительно, если трогали сессию или плеер:

```bash
pnpm proxy:dev                  # терминал 1
pnpm mobile:android             # терминал 2
pnpm e2e:pause:open             # терминал 3, ожидание exit 0
```

Если трогали работу с Gemini — прогнать сессию с реальным ключом, а не только
в фейк-режиме: `EXPO_PUBLIC_FAKE_GEMINI=1` проверяет проводку, но не
договорённость с моделью о формате ответа.

## Чего в процессе пока нет

Честный список, чтобы не было сюрпризов:

- **OTA ни разу не публиковался.** `eas update:list` на 2026-07-22 пуст.
  Первая выкатка будет и первой проверкой канала.
- **Откат не проверялся на живом устройстве** — команды существуют и
  документированы, но в бою не применялись.
- **Нет экспорта данных.** Переустановка APK стирает словарь и прогресс.
- **Уведомления работают только в APK**, в Expo Go модуль недоступен.
