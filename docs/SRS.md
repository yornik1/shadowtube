# SRS: карточки и интервальные повторения

Как устроены повторения в ShadowTube и как их тестировать без устройства.

## Откуда берутся карточки

Во время сессии:

1. Тап по слову — выделение; второй тап по другому слову — диапазон между ними
   (`src/session/spanSelection.ts`). Пробелы кликабельны и отдаются соседнему
   слову: тап «мимо буквы» не должен выглядеть как зависшее приложение.
2. «Перевести» → `PhraseSheet` → `translatePhrase()` переводит **выделенный
   отрезок в контексте всего чанка** и одним ответом отдаёт русский перевод,
   дословный вариант, английское определение и пометку про идиому.
3. «＋ В словарь» — запись в `vocabulary` с `due_at = now`, поэтому карточка
   доступна к повторению сразу.

Кнопка «＋ чанк» в сессии сохраняет предложение целиком — для «лучших фраз
сессии», когда разбирать по кускам не хочется.

## Модель карточки

Одна запись словаря = одна карточка. Режим (`Настройки → Карточки повторения`)
меняет только подачу, интервалы общие — иначе очередь раздувалась бы втрое.

| Режим | Лицо | Оборот |
|-------|------|--------|
| `ru_to_en` (по умолчанию) | русский перевод | английская фраза + предложение |
| `en_to_ru` | английская фраза | русский перевод |
| `en_to_en` | английская фраза | английское определение, русский — по кнопке |

`en_to_en` для записей, сохранённых до появления `definition_en`, молча
откатывается на перевод — пустых карточек быть не должно.

## Интервалы (FSRS на трёх оценках)

`src/srs/fsrs.ts` поверх пакета `ts-fsrs`. FSRS описывает память тремя
величинами вместо одного «ease factor»: **stability** (сколько дней
продержится), **difficulty** (тяжесть карточки лично для тебя) и
**retrievability** (вероятность вспомнить сейчас). Коэффициенты обучены на
сотнях миллионов реальных повторений, и при той же удерживаемости FSRS даёт
на 20-30% меньше показов, чем SM-2.

Целевая удерживаемость — `DEFAULT_RETENTION = 0.9`.

Три кнопки UI маппятся так:

| Кнопка | Rating в FSRS |
|--------|---------------|
| Не помню | `Rating.Again` |
| Трудно | `Rating.Hard` |
| Легко | **`Rating.Good`** |

«Легко» намеренно НЕ маппится в `Rating.Easy`: Easy это «настолько легко, что
закинь очень далеко», он применяет отдельный бонусный множитель, и интервалы
начали бы разлетаться. `Rating.Good` — нормальный успешный ответ.

Планировщик создаётся с `enable_short_term: false`. По умолчанию FSRS ставит
свежую карточку в learning-шаги на минуты, из-за чего `scheduled_days`
получается 0 — для приложения, где повторяют раз в день, это ломает и
интервалы, и очередь.

**SM-2 остался** в `src/srs/sm2.ts` вместе с колонками `ef` / `interval_days`
как путь отката. Новые колонки: `stability`, `difficulty`, `fsrs_state`,
`elapsed_days`, `scheduled_days`.

## Откуда берутся карточки автоматически

`src/srs/autoCards.ts`. Модель в пакетном ответе возвращает по каждому чанку
список фраз с оценкой полезности 1-5, и карточки создаются в момент, когда
человек **открыл перевод** чанка — то есть реально с ним разбирался.

Предохранители против затопления очереди (в трёхчасовом видео 1234 чанка, а
дневная норма — 10 карточек):

- только `worth >= 4` и `kind != "plain"`;
- максимум 2 карточки с одного чанка, 15 за сессию;
- отсев мусора автосабов: `--`, дефис рядом с пробелом, скобки, `[Music]`;
- дедупликация по нормализованному тексту;
- тост «+N карточки» — процесс виден, а не происходит втихую;
- выключается в Настройках.

«Не помню» возвращает карточку в конец **текущего** захода, а не через день:
забытое закрепляется в этой же сессии (`app/(tabs)/review.tsx`).

## Мотивация

`src/srs/streak.ts`:

- дневная норма — 10 карточек (`DEFAULT_DAILY_GOAL`);
- день засчитывается в цепочку **при выполнении нормы** — иначе одна карточка
  в день поддерживала бы «цепочку в 40 дней», ничему не научив;
- дни сравниваются по локальному календарю: цепочка ломается в полночь
  пользователя, а не в UTC;
- `atRisk` — норма выполнена вчера, но не сегодня: цепочка сгорит в полночь;
- состояние лежит в таблице `app_state` (не в SecureStore: это данные учёбы,
  они должны удаляться вместе со словарём).

Бейдж с числом карточек на вкладке — `src/srs/dueStore.ts`, обновляется сразу
после сохранения фразы, без перехода на вкладку.

## Уведомления

`src/srs/notifications.ts`, ежедневно в 20:00, включается в настройках.

**В Expo Go на Android не работают.** `expo-notifications` с SDK 53 падает
**на импорте модуля**, а не на вызове API, поэтому модуль грузится лениво через
`require()` внутри функции — статический import уронил бы весь бандл. Проверять
только на собранном APK:

```bash
pnpm build:apk:preview
```

В Expo Go экран настроек показывает это ограничение текстом вместо кнопки.

### Проверка на устройстве без ключа Gemini

Ключ BYOK есть не на каждом устройстве и его нельзя держать в репозитории,
поэтому вся цепочка проходится с фейковым переводчиком:

```bash
EXPO_PUBLIC_FAKE_GEMINI=1 SHADOWTUBE_USE_LOCAL_PROXY=1 pnpm mobile
```

Gemini не вызывается, переводы приходят помеченными «[тест]», в Настройках
висит жёлтый баннер — фейк не должен молча притворяться настоящим переводом.
Заготовлены осмысленные ответы для `get away with`, `figure out`, `in a room`,
для остальных фраз ответ генерируется по шаблону.

На эмуляторе проверяется то, что нельзя проверить чисто:

- **миграция со старой БД** — поставить старую сборку, добавить слова, накатить
  новую: словарь должен остаться, `due_at` у старых записей заполниться из
  `added_at`;
- рендер выделения и лист перевода;
- цикл повторения на 3 карточках.

Логи с устройства: `curl -s http://localhost:8787/log/tail | grep '\[e2e\]'`.
События повторений: `review_open`, `review_show_answer`, `review_grade`,
`review_done`; события выделения: `select`, `translate_phrase`, `save_chunk`.
